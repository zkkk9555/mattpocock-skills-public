# Usage log + evolution gate — 使用日志与升级门

> 为什么要有日志：你用 skill 时遇到卡点、选错 skill、被迫纠正，这些是下次升级（下一个 V2.00N）唯一的真实素材。日志只记录、不自治，保证升级可控。

## 记哪里：一本中央日志，不进 skill 包

所有 Agent 共用**一本**日志（一个安装只有一本，不分语言、不分项目；条目语言由安装者定并全程一致，driver 不询问）。位置由安装者固定：

`~/.autopilot/USAGE-LOG.md (installer default; override with any fixed path outside repos)`

每次跑完一个 autopilot 任务，往这本**追加一条**（只追加、不改旧条）。skill 自己的目录（`SKILL.md`、`references/`、`agents/`、`CHANGELOG.md`、`VERSION`）永远不写日志——菜谱和流水分开，版本才干净；多任务并发写同一本时，整条一次写完，不要分两次写半条——推荐用 shell 整条 append（`cat >> … <<'EOF'`），实测比 Edit 工具更能避开并行 driver 的写冲突。

如果这个固定路径写不进去（比如在别的机器上跑），退回记在当前任务的 `.scratch/<slug>/USAGE-LOG.md`，并在条里注明“中央本不可写，已记本地”。

**首本自建**：中央本路径不存在（全新安装）→ 按示例格式（`USAGE-LOG.example.md` 五方面 + 头部规则）新建一本再追加，而不是直接退回本地。安装脚本通常已建好首本；这条是没跑安装脚本时的自愈。示例文件本身永远不写——它是格式说明书，不是账本。

**跨 harness（V2.013）**：日志本是本机文件，不跟着版本走。换 harness 时交接包必须写明中央本的本机绝对路径；新 harness 上中央本不可写 → 走本地 `.scratch/` 并注明，回来后把本地条合并回中央本（append，不改旧条）。反思计数同理：按新 harness 本地条目续数，合并时注明来源。

## 什么时候写：任务收尾自动写，不用用户提醒（V2.004）

写日志是 driver 收尾动作的一部分，不是用户下指令才做的事。触发条件只有一个：**这个任务在你这一轮结束**（交付了、STOP 了、BLOCKED 了，都算结束），你就写。用户只需要负责触发 skill，剩下的不用管。

- 一个任务只写一条，写在任务结束的那一轮，不要每轮都写。
- 跨轮的任务（第一轮没做完，第二轮接着做）不用每轮记，记一条就行，写在收尾那一轮，“经过”里把几轮拼起来。
- 写不进中央本（比如在别的机器上跑）才退回本地 `.scratch/<slug>/USAGE-LOG.md`，并注明“中央本不可写，已记本地”。

## 任务和轮次的区别（V2.004：第二轮没调 skill 也要自查）

先把两个词分开，一个任务可能跨好多轮：

- **任务** = 用户一句话交代的事（比如“修切换按钮”），从接单到交付/STOP/BLOCKED 算一个任务，日志**按任务**记，一任务一条。
- **轮次** = 一次对话回合。有的轮次 driver 大干一场（调了一串 skill），有的轮次只是回一句话、等用户补日志、或者用户根本没调 skill。

第二轮没调 skill 有两种，处理不一样：

1. **driver 还在，只是这轮没活干**（比如等用户补复现步骤、回答问题）：不用写日志条，但在 JOURNAL 那行里记一笔“本轮无 skill 调用，原因：等用户补 XX”，下一轮接着干，收尾时那一条日志把这轮也算进去。
2. **用户新开一轮，driver 被重新触发**（读到自举、T0 ask-matt 又转起来了）：这就是新一轮的 driver 在干活，收尾时照样写一条，任务名后面注明“接续第 N 轮”。

所以“第二轮没用 skill，它还会跑工作流吗”——答案是：它每轮自举时都会对照 core-triggers 过一遍，该转就转；转了没，转了什么，都在收尾那条日志里交代。你不用在第二轮提醒它，它自己记得。

“记五行”不是只写 5 行，是 5 个方面，每个方面可写多行：

1. **经过**：这次任务从头到尾怎么回事？用户说了什么，driver 按顺序走了哪几个 skill。
2. **为啥用**：每个 skill 为什么调？对照 `references/core-triggers.md` 的哪条入口条件命中的？——这是给你这种不会工作流的用户准备的：你看不懂对不对没关系，driver 必须自己写出“因为命中了哪条所以调了谁”，你只看这句顺不顺。
3. **卡点**：哪里犹豫了、绕路了、输出质量差了？你纠正了哪一句（原话尽量记）？没纠正就写“用户未纠正”。
4. **漏用自查**：对照 `core-triggers.md` 的 8 核心，有没有“该用没用”的？有就写哪条 + 为什么当时没调；没有就写“无”。——“该用没用”系统记不住，只能靠 driver 自己每轮对照 8 条过一遍，这是 V2.003 的硬规则。
5. **结果**：交付了吗（`delivery-check.md` 三件套齐了吗）？verify 贴绿了吗？你亲手点了吗？

用户不会工作流、不纠正，不缺数据：第 2 条（为啥用）和第 4 条（漏用自查）就是 driver 的自我交代，你下次把日志本拿回来，skill-creator 看的是这两条写得诚不诚实，而不是等你去判对错。

## 升级怎么用它

过一段时间，你把中央日志本拿回来，开一轮 skill-creator（就是 V2.002 这一轮做的事），按日志里的高频卡点出 V2.00N。升级是工程动作（改文件 → commit → 打 tag → 手工镜像到自用库），不是 driver 自己做的。

## 定期反思：每 3 个工程轮，driver 自答升级问题（V2.007）

升级素材有两个来源：任务日志记**事实**（这轮发生了什么），反思记**设计观察**（这套流程哪里不顺）。反思是 driver 写给日志本的，不是问用户的——不打断任务、不违反 AFK 原则。

**触发**：本会话每完成第 3 个工程轮（有真实 skill 调用的轮），在那轮的任务收尾、任务日志写完**之后**，往中央日志本追加一条反思。计数跟着 WORKFLOW-ACTIVE 标记走：任务存活期标记里写 `工程轮次: N`；任务收尾会删标记，所以下一轮是**重建标记时写上轮计数 +1**，不是原地更新——计数本体始终留在会话上下文里。计数拿不准时保守处理——本会话明显已干满 3 轮就反思。误差无害，宁多勿少。反思只在收尾时做，绝不打断任务中间。条目里的"第N次"= 本会话的第几次反思（会话内从 1 数起）。

两条兜底（V2.008）：①规则中途引入、或上下文压缩后计数丢失——按中央日志本数该项目最近的任务条目 + `[反思]` 条目重建计数，**日志即真相源**；②会话开始时已明显 ≥3 个工程轮 → 下一轮收尾立即补首次反思，不等凑满下个 3 的倍数。

**条目格式**（追加到中央日志本，和任务条目分开）：

```markdown
## [反思] <日期> 第N次（项目：<项目>）

> 这个 skill 的终极目标：用户说一句日常人话，你就能全自动完成整个任务，交付稳定、可验证的成果，中途不需要任何人参与。唯一的例外：碰到删数据、花钱、对外发布这类高危操作时，停下来等人拍板。

1. 调用时机：……
2. 含糊：……
3. 偏方：……
4. 差距：……
5. 其他：……
```

**五问原文**（每问引用最近这几轮实际发生的事，2-4 行；先扫日志本尾部几条，已修过的不重报，只报本次会话新发现；没有发现就写"无"，禁止为了交差编造建议）：

1. **调用时机**：这几轮干活时，有没有哪个时刻你觉得"现在该调 autopilot 或它的某个工作流能力"，但没有任何机制提醒你、于是没调？现有检查点——开局分流、动手前自查、每段干完 15 秒自扫、交付前评审——哪些真的拦住过你，哪些你完全没感觉到存在？如果让你自己设计"什么时候该回去问一次工作流"，你会把检查点放在哪几个时刻？
2. **含糊**：哪条规则读着含糊、前后矛盾、或压根没用上？举例。
3. **偏方**：你有没有自创什么做法来绕开规则？它比规则好吗？值得转正吗？
4. **差距**：对照开头的终极目标，这几轮暴露的最大差距是什么？只写最重要的一条。
5. **其他**：还有想说的吗？没有就写"无"。

**铁律不变**：反思只进日志，绝不因此改 skill 自己的文件；升级仍走"中央日志 → skill-creator 出新版"。

## 自进化门：只提案，不自改（硬规则）

- driver **永远不改**自己的 `SKILL.md`、`references/`、`agents/`、`CHANGELOG.md`、`VERSION`。即使发现自己的触发条件写错了，也照当前规则把活干完，把想法写进 `.scratch/<slug>/DRIVER-PROPOSAL.md`（坏在哪 + 证据 + 建议改法），然后继续。
- 自己改自己 = malformed（和 T0-only 一样，属于坏轮，要在 trace 里记 deviation）。
- 全自动自进化不做：自己改触发器会悄悄改坏 25 个上游 skill 的零碰线、版本号乱掉、和 goal 模式的记忆打架。进化只走“中央日志 → 你拿回来 → skill-creator 出新版”这条路。
