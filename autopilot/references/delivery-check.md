# Delivery check — 给不会写代码的你的交付门

> 判据：你不需要看代码，但必须能亲手验出“稳定”。三件不齐 = 没交付，driver 不许收尾、不许说“做完了”。

## 三件套（每个小活必须给）

1. **改了哪里一句话**：中文一句话，说清改了哪个功能、影响哪里。不贴代码。
2. **手工清单**：你照着点一遍就能验。写法是“点哪里 → 看到什么 = 过”。例如：点“新增”按钮 → 弹出发票行 → 保存后列表多一行。每条都要有“看到什么算过”，含糊的（“应该可以了”）不算。优先给**复制粘贴即可执行的一条命令或一个链接**——无 UI 可点的任务（V2.008：AFK 用户最方便的就是跑一条命令看输出），点击步骤次之。
3. **verify 原文输出**：跑仓库验证命令，把完整输出贴出来（红就是没完工，不用你看懂）。红 = 继续修，不许收尾；绿 + 你手工全过 = 才叫交付。

## 高危 STOP（出现就停，等你点头）

删数据、改已发布历史、发版/提交到外部、花钱、动 credential、合规/法务/上架、升级引擎或依赖、引入新系统/依赖/流水线/外部服务/成本——先写 `.scratch/<slug>/NEEDS-HUMAN.md`（是什么、为什么停、要你定什么），然后停住当前 turn。其他小活默认往前冲，不问你。

## 可见性（你只看对话就行）

driver 控制不了 harness 的“思考过程显示”，能控制的是自己的正文。每轮可见回复**首句**写：`本轮调用：A、B、C（各一句为什么）`，中文。例如：“本轮调用：ask-matt（分流）→ diagnosing-bugs（有必现报错，先建反馈环）”。JOURNAL 里那行英文 `Skills called:` 继续保留，只做 grep 对账，不给你看也行。HTML 看板、COVERAGE 清单都不建——你说过看不懂、没用，V2.002 彻底砍掉。

## 样子（V2.005：照着写，别各写各的）

首句如上：中文名 + 括号一句为什么，调用顺序用 → 连。
改哪里一句话如：修了小灯切换按钮的显示同步，文字变时灯的外观也跟着亮/灭，别处不动。
手工清单如：点一次切换，灯文字变开且灯变亮算过；再点一次，文字变关且灯变暗算过。
verify：贴完整命令 + 输出 + EXIT 码，红（非零）在先、绿（0）在后是同一命令。

## 仓库无验证命令时（V2.005）

无 README 验证命令、无测试 runner → 按 verification-gates no-harness 回退：自发明单文件 seam 断言（红=非零退出+信号行，绿=0）+ 一次冒烟，当 verify 原文贴出来，并注明自发明断言、非仓库自带。
